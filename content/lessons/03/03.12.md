Measured signals aren't formulas: they're lists of samples from an accelerometer or a microphone. The discrete Fourier transform (DFT) turns those samples into frequency content, and the fast Fourier transform (FFT) computes it in $O(N\log N)$ operations instead of $O(N^2)$. That speed-up is why every vibration analyser, spectrum app and audio codec can work in real time.

## The DFT

For $N$ samples $x_0, \dots, x_{N-1}$ taken at rate $f_s$:

$$
X_k = \sum_{n=0}^{N-1}x_n\,e^{-2\pi i\,kn/N}, \qquad k = 0, \dots, N - 1 .
$$

Bin $k$ corresponds to frequency $f_k = k f_s/N$. Two numbers set what you can see:

- **Resolution** $\Delta f = f_s/N = 1/T$, where $T$ is the record length. To separate peaks 0.5 Hz apart, record at least 2 s.
- **Nyquist frequency** $f_s/2$. Anything above it aliases (lesson 00.08). Only bins up to $N/2$ carry information for real signals.

A sine of amplitude $A$ exactly on bin $k$ gives $|X_k| = AN/2$, so the one-sided amplitude spectrum is $2|X_k|/N$.

## Why it's fast

Split the sum into even and odd samples:

$$
X_k = E_k + e^{-2\pi ik/N}O_k, \qquad X_{k+N/2} = E_k - e^{-2\pi ik/N}O_k,
$$

where $E$ and $O$ are DFTs of length $N/2$. One length-$N$ transform becomes two of length $N/2$ plus $N$ multiplications. Recursing gives $N\log_2N$ work. For $N = 2^{20}$ that's about 20 million operations instead of $10^{12}$.

## Leakage and windows

The DFT assumes the record repeats forever. If a sine doesn't fit a whole number of periods in the record, the repeated signal has a jump, and its energy leaks into neighbouring bins. Multiplying the record by a smooth **window** (Hann: $w_n = \sin^2(\pi n/N)$) tapers the ends to zero and confines the leakage, at the cost of a slightly wider peak. Correct the amplitude by the window's mean (0.5 for Hann).

:::example Finding the vibration in a pump
An accelerometer samples at $f_s = 1024$ Hz for $T = 1$ s ($N = 1024$). The signal is 2.0 m/s² at 50 Hz (rotor imbalance) plus 0.5 m/s² at 120 Hz (vane pass) plus noise.

1. Resolution $\Delta f = 1$ Hz, Nyquist 512 Hz. Both tones sit exactly on bins 50 and 120.
2. The FFT's one-sided amplitudes at those bins come out at 2.00 and 0.50 m/s² (the code checks it).
3. Now the rotor speeds up slightly to 50.5 Hz, halfway between bins. Without a window the peak reads only 1.28 m/s², spread over many bins. With a Hann window (corrected by its mean of 0.5) the peak reads 1.70 m/s², and the leakage ten bins away is about 80 times smaller.
4. Lessons: choose $T$ for the resolution you need, use a window for amplitudes between bins, and don't trust a single bin's amplitude to better than about 15% without one.
:::

```python file=fft.py
"""A recursive radix-2 FFT checked against NumPy, plus resolution, leakage and windowing."""
import cmath
import math
import time
import numpy as np


def fft(x):
    n = len(x)
    if n == 1:
        return [complex(x[0])]
    if n % 2:
        raise ValueError("length must be a power of two")
    E, O = fft(x[0::2]), fft(x[1::2])
    tw = [cmath.exp(-2j * math.pi * k / n) * O[k] for k in range(n // 2)]
    return [E[k] + tw[k] for k in range(n // 2)] + [E[k] - tw[k] for k in range(n // 2)]


def dft(x):
    n = len(x)
    return [sum(x[m] * cmath.exp(-2j * math.pi * k * m / n) for m in range(n)) for k in range(n)]


def amplitude_spectrum(x, window=None):
    n = len(x); w = np.ones(n) if window is None else window
    X = np.fft.rfft(x * w)
    return 2 * np.abs(X) / (n * w.mean())


if __name__ == "__main__":
    rng = np.random.default_rng(14)
    x = rng.standard_normal(256)
    assert np.allclose(fft(list(x)), np.fft.fft(x)) and np.allclose(dft(list(x[:64])), np.fft.fft(x[:64]))
    for n in (256, 1024):
        s = list(rng.standard_normal(n))
        t = time.perf_counter(); fft(s); tf = time.perf_counter() - t
        t = time.perf_counter(); dft(s[:256]); td = (time.perf_counter() - t) * (n / 256) ** 2
        print(f"N = {n}: recursive FFT {tf*1e3:6.1f} ms, DFT (scaled estimate) {td*1e3:8.0f} ms")
    fs, N = 1024, 1024
    t = np.arange(N) / fs
    sig = 2.0 * np.sin(2 * math.pi * 50 * t) + 0.5 * np.sin(2 * math.pi * 120 * t) + 0.05 * rng.standard_normal(N)
    A = amplitude_spectrum(sig)
    print(f"bins 50 and 120: {A[50]:.3f}, {A[120]:.3f} m/s^2")
    assert abs(A[50] - 2) < 0.02 and abs(A[120] - 0.5) < 0.02
    off = 2.0 * np.sin(2 * math.pi * 50.5 * t)
    rect, hann = amplitude_spectrum(off), amplitude_spectrum(off, np.sin(math.pi * np.arange(N) / N) ** 2)
    print(f"50.5 Hz tone: rectangular peak {rect.max():.2f}, Hann peak {hann.max():.2f}; 10 bins away {rect[60]:.4f} vs {hann[60]:.5f}")
    assert 1.2 < rect.max() < 1.35 and 1.6 < hann.max() < 1.8 and rect[60] > 50 * hann[60]
```

:::exercise Plan a measurement
You want to resolve two gear-mesh tones at 312 Hz and 313.5 Hz and capture harmonics up to 2 kHz. What minimum sample rate and record length do you need, and how many samples is that?
---solution---
1. Harmonics to 2 kHz need $f_s > 4$ kHz; with an anti-alias filter margin, use about 5 kHz (5120 Hz is a common choice).
2. To separate peaks 1.5 Hz apart you need $\Delta f$ well below 1.5 Hz; with a Hann window the main lobe is about $4\Delta f$ wide, so take $\Delta f = 0.25$ Hz, meaning $T = 4$ s.
3. Samples: $N = f_sT = 5120\cdot4 = 20\,480$, or round up to $2^{15} = 32\,768$ (6.4 s) for a radix-2 FFT.
:::
