OpenFOAM is the most widely used open-source CFD toolbox: a C++ library of finite-volume operators plus around a hundred solvers. Its tutorial number one is the lid-driven cavity, solved by **icoFoam**, a transient incompressible laminar solver. Running the same problem in OpenFOAM and in the course's own MAC solver from the projection lesson is the best way to learn what a professional case contains, and to check both codes.

## Anatomy of a case

An OpenFOAM case is a directory of plain-text dictionaries:

- `system/blockMeshDict`: the mesh, as hexahedral blocks. 2D cases are one cell thick with `empty` front and back patches.
- `system/controlDict`: time step, end time, output.
- `system/fvSchemes`: how each term is discretised: `Euler` in time, `Gauss linear` (central) for gradients, divergence and Laplacian.
- `system/fvSolution`: the linear solvers (PCG with DIC preconditioning for pressure, Gauss-Seidel for velocity) and the **PISO** pressure-velocity algorithm with 2 correctors.
- `constant/transportProperties`: $\nu$.
- `0/U`, `0/p`: initial and boundary conditions. The lid is `fixedValue (1 0 0)`, the other walls `noSlip`, the pressure `zeroGradient` everywhere (fixed at one reference cell).

Then `blockMesh`, `checkMesh` and `icoFoam` run it. PISO is a projection method like Chorin's, but on a collocated grid with Rhie-Chow interpolation of the face fluxes, and with the momentum equation solved implicitly.

The case used here, at $Re = 100$ on 64 × 64 cells:

**How this was run.** OpenFOAM v1912 (the Debian package) was installed on the machine that builds this course, and the case ran to $t = 30$ with $\Delta t = 0.004$ (maximum Courant number 0.24) in 28 s. `checkMesh` reported non-orthogonality 0 and "Mesh OK". The code below stores icoFoam's centreline velocities, so it runs anywhere; with OpenFOAM installed, `RUN_OPENFOAM=1` writes the full case to a temporary directory and reruns it.

:::example Two codes, one answer
| Quantity | icoFoam | Own MAC solver | Ghia et al. |
|---|---|---|---|
| $u_{min}$ on $x = 0.5$ | −0.2125 | −0.2128 | −0.2109 |
| $v_{max}$ on $y = 0.5$ | 0.1784 | 0.1785 | 0.1753 |
| $v_{min}$ on $y = 0.5$ | −0.2525 | −0.2527 | −0.2453 |
| Max deviation from Ghia, $u$ / $v$ | 0.0034 / 0.0087 | 0.0038 / 0.0086 | |

1. The two codes differ by at most 0.0005 in $u$ and 0.0004 in $v$ anywhere on the centrelines: far less than either differs from Ghia.
2. So the remaining gap to Ghia is not a bug in either code. It is the **discretisation error of a 64 × 64 grid**, which both second-order schemes share (Ghia used 129 × 129).
3. The codes are genuinely different: collocated against staggered, implicit PISO against explicit projection, iterative against direct pressure solves. Agreement between independent implementations is one of the strongest verification checks there is.
:::

def run_openfoam():
    d = tempfile.mkdtemp(prefix="cavity_")
    for name, text in CASE.items():
        os.makedirs(os.path.join(d, os.path.dirname(name)), exist_ok=True)
        open(os.path.join(d, name), "w").write(text)
    env = dict(os.environ, FOAM_ETC=os.environ.get("FOAM_ETC", "/usr/share/openfoam/etc"))
    for app in ("blockMesh", "icoFoam"):

def mac_cavity(N=64, Re=100.0, tmax=60.0, tol=1e-6):
    """Chorin projection on a MAC grid (as in the projection lesson)."""
    h = 1.0 / N
    dt = min(0.2 * h * h * Re, 0.5 * h)
    L = (np.diag(-2.0 * np.ones(N)) + np.diag(np.ones(N - 1), 1) + np.diag(np.ones(N - 1), -1)) / h**2
    L[0, 0] = L[-1, -1] = -1 / h**2
    lam, V = np.linalg.eigh(L)
    den = lam[:, None] + lam[None, :]
    k0 = np.argmin(abs(lam)); den[k0, k0] = np.inf
    U = np.zeros((N + 1, N + 2)); W = np.zeros((N + 2, N + 1))
    def ghosts():
        U[:, 0] = -U[:, 1]; U[:, -1] = 2 - U[:, -2]; W[0, :] = -W[1, :]; W[-1, :] = -W[-2, :]
    t, it = 0.0, 0
    while t < tmax:
        ghosts()
        uc = 0.5 * (U[1:, 1:-1] + U[:-1, 1:-1]); vc = 0.5 * (W[1:-1, 1:] + W[1:-1, :-1])
        uv = 0.5 * (U[:, 1:] + U[:, :-1]) * 0.5 * (W[1:, :] + W[:-1, :])
        lu = (U[2:, 1:-1] + U[:-2, 1:-1] + U[1:-1, 2:] + U[1:-1, :-2] - 4 * U[1:-1, 1:-1]) / h**2
        lv = (W[2:, 1:-1] + W[:-2, 1:-1] + W[1:-1, 2:] + W[1:-1, :-2] - 4 * W[1:-1, 1:-1]) / h**2
        Fu = -(uc[1:] ** 2 - uc[:-1] ** 2) / h - (uv[1:-1, 1:] - uv[1:-1, :-1]) / h + lu / Re
        Fv = -(vc[:, 1:] ** 2 - vc[:, :-1] ** 2) / h - (uv[1:, 1:-1] - uv[:-1, 1:-1]) / h + lv / Re
        U[1:-1, 1:-1] += dt * Fu; W[1:-1, 1:-1] += dt * Fv
        div = (U[1:, 1:-1] - U[:-1, 1:-1] + W[1:-1, 1:] - W[1:-1, :-1]) / h
        p = V @ ((V.T @ (div / dt) @ V) / den) @ V.T
        U[1:-1, 1:-1] -= dt * (p[1:] - p[:-1]) / h; W[1:-1, 1:-1] -= dt * (p[:, 1:] - p[:, :-1]) / h
        t += dt; it += 1
        if it % 200 == 0 and max(np.max(abs(Fu - (p[1:] - p[:-1]) / h)), np.max(abs(Fv - (p[:, 1:] - p[:, :-1]) / h))) < tol:
            break
    return U[N // 2, 1:-1], W[1:-1, N // 2], it

:::exercise Reading the case
In the tutorial, the cavity is 0.1 m across with $\nu = 0.01$ m²/s and a lid speed of 1 m/s. What is its Reynolds number? What would you change in which file to run this lesson's $Re = 100$ case on the tutorial geometry?
---solution---
1. $Re = UL/\nu = 1 \times 0.1/0.01 = 10$.
2. Either set `nu 0.001;` in `constant/transportProperties`, or keep $\nu$ and set the lid to `(10 0 0)` in `0/U`. Changing $\nu$ keeps the time step stable; a lid speed 10 times faster would need a 10 times smaller `deltaT` in `system/controlDict` for the same Courant number.
:::
