Most of the controllers in the world are PID loops: cruise control, the temperature of an espresso machine, the pressure in a water network, the pitch of a drone. Three terms, three gains, and a few practical fixes that separate a textbook PID from one that works on a real machine.

## The three terms

With the error $e = r - y$, the controller output is

$$
u(t) = K_p\,e(t) + K_i\int_0^t e\,d\tau + K_d\,\frac{de}{dt} .
$$

- **P** reacts to the present error. Alone it leaves a **steady-state error** whenever the plant needs a non-zero input to hold the set-point: on a hill the motor must push, so the error cannot be zero.
- **I** accumulates past error. The integral keeps growing until the error is exactly zero, so integral action **removes the steady-state error** against any constant disturbance.
- **D** reacts to the trend. It adds damping, but it amplifies measurement noise, so in practice it is filtered or taken on the measurement only.

For a P controller on a plant that needs a force $F_\text{need}$ at the set-point and has a damping slope $c$, the steady error is $e_\infty \approx F_\text{need}/(K_p + c)$. Raising $K_p$ reduces it but never removes it, and the loop goes unstable long before it gets small.

## Ziegler-Nichols tuning

Ziegler and Nichols (1942) gave a recipe that still works as a first guess. Raise a P gain until the loop just oscillates: that is the **ultimate gain** $K_u$ with period $T_u$ (lesson 18.11 computes both). Then

| Controller | $K_p$ | $T_i = K_p/K_i$ | $T_d = K_d/K_p$ |
|---|---|---|---|
| P | $0.5K_u$ | | |
| PI | $0.45K_u$ | $T_u/1.2$ | |
| PID | $0.6K_u$ | $T_u/2$ | $T_u/8$ |

These gains are aggressive, aiming at a quarter-amplitude decay per cycle. Most loops are then detuned by hand.

## Saturation and integrator windup

Real actuators have limits: an e-bike motor gives at most 80 N here. On a steep hill the controller asks for more than the motor can give, the error stays large, and the integral keeps **winding up**. At the crest the huge integral keeps the motor at full force long after the speed is back, and the bike overshoots badly. **Anti-windup** stops the integrator while the actuator is saturated and the error would drive it further in (clamping), or bleeds it back by the excess (back-calculation).

:::example Cruise control for an e-bike
Rider and bike $m = 100$ kg, drag area $C_dA = 0.5$ m², $C_{rr} = 0.006$, motor limit 80 N, motor lag 0.2 s, speed filter 0.3 s, set-point 25 km/h.

1. **Linearise** at 25 km/h: the drag slope is $c = \rho C_dA v = 4.17$ N·s/m, so the bike alone has a time constant $m/c = 24.0$ s. The loop with the two lags is third order.
2. **Ultimate gain** by bisection on the closed-loop poles: $K_u = 850.78$ N per m/s, $T_u = 1.5233$ s. Routh gives the same $K_u$. Ziegler-Nichols PID: $K_p = 510.5$, $T_i = 0.762$ s, $T_d = 0.190$ s.
3. **3 % hill, P only** with $K_p = 0.3K_u = 255.2$: the bike loses 0.691 km/h. The linear formula, $(14.47 + 5.89 + 29.42\text{ N})/(255.2 + 4.17)$, gives the same 0.691 km/h.
4. **Add integral action** ($K_i = 41.9$, $T_i = 4T_u$): the error at the end of the hill is 0.0007 km/h. The ZN PID holds the speed within 0.30 km/h through the start of the hill.
5. **8 % hill**: the motor saturates and the bike slows to 9.45 km/h whatever the controller does. Without anti-windup it then overshoots by 24.84 km/h past the crest, nearly doubling the speed. With clamping the overshoot is 0.62 km/h.
:::

```python file=pid_ebike.py
"""PID cruise control of an e-bike: a non-linear speed model with drag, rolling resistance, hills,
a motor force limit and lags. P alone leaves an error on a hill, integral action removes it, a steep
hill saturates the motor and winds up the integrator, and clamping anti-windup fixes the overshoot.
Ziegler-Nichols gains come from the ultimate gain of the linearised loop. numpy only."""
import numpy as np

m, g, rho, CdA, Crr = 100.0, 9.81, 1.2, 0.5, 0.006       # rider + bike, air, drag area, rolling
Fmax, tau_a, tau_s = 80.0, 0.2, 0.3                        # motor force limit N, motor lag s, speed-filter lag s
v_ref = 25 / 3.6

def grade(t, steep):
    return (0.08 if steep else 0.03) if 20 <= t < 60 else 0.0

def simulate(Kp, Ki, Kd, steep=False, antiwindup=True, T=100.0, dt=0.002):
    v, F, vm, I, e_prev = v_ref, 0.0, v_ref, 0.0, 0.0
    F = 0.5 * rho * CdA * v_ref**2 + Crr * m * g             # start in steady cruise on the flat
    I = F / Ki if Ki else 0.0
    n = int(T / dt); out = np.empty((n, 3))
    for k in range(n):
        t = k * dt
        e = v_ref - vm
        D = (e - e_prev) / dt if k else 0.0; e_prev = e
        u = Kp * e + Ki * I + Kd * D
        u_sat = min(max(u, 0.0), Fmax)                       # the motor can only push, up to 80 N
        if not antiwindup or u == u_sat or (u > Fmax and e < 0) or (u < 0 and e > 0):
            I += e * dt                                      # clamping: freeze the integrator while it would push further into saturation
        F += dt * (u_sat - F) / tau_a
        th = np.arctan(grade(t, steep))
        a = (F - 0.5 * rho * CdA * v * abs(v) - Crr * m * g * np.cos(th) - m * g * np.sin(th)) / m
        v += a * dt
        vm += dt * (v - vm) / tau_s
        out[k] = t, v, u_sat
    return out

# linearised loop at cruise: G = 1/(m s + c) * 1/(tau_a s + 1) * 1/(tau_s s + 1), c = rho CdA v
c = rho * CdA * v_ref
den = np.polymul([m, c], np.polymul([tau_a, 1], [tau_s, 1]))
Ku = None
lo, hi = 1.0, 1e5
for _ in range(200):
    mid = np.sqrt(lo * hi)
    if np.max(np.roots(np.polyadd(den, [mid])).real) > 0: hi = mid
    else: lo = mid
Ku = lo; wu = np.max(np.abs(np.roots(np.polyadd(den, [Ku])).imag)); Tu = 2 * np.pi / wu
a1, a2, a3 = den[1] / den[0], den[2] / den[0], den[3] / den[0]
print(f"linearised plant time constant m/c = {m/c:.2f} s; ultimate gain Ku = {Ku:.3f} N/(m/s), Tu = {Tu:.4f} s (Routh: Ku = {(a1*a2-a3)*den[0]:.3f})")
assert abs(Ku - (a1 * a2 - a3) * den[0]) < 1e-6 * Ku
Kp, Ti, Td = 0.6 * Ku, Tu / 2, Tu / 8                       # classic Ziegler-Nichols PID
print(f"Ziegler-Nichols PID: Kp = {Kp:.2f}, Ti = {Ti:.4f} s, Td = {Td:.4f} s")
Kp_t, Ki_t = 0.3 * Ku, 0.3 * Ku / (4 * Tu)                  # a gentler PI for the cruise tests: Kp = 0.3 Ku, Ti = 4 Tu

err = lambda o, t0, t1: np.mean(v_ref - o[(o[:, 0] > t0) & (o[:, 0] < t1), 1]) * 3.6
P = simulate(Kp_t, 0, 0)
PI = simulate(Kp_t, Ki_t, 0)
print(f"3 % hill, P only (Kp = {Kp_t:.1f}): speed error at the end of the hill {err(P, 55, 60):.3f} km/h (linear theory: total force needed / (Kp + c) = {(0.5*rho*CdA*v_ref**2 + Crr*m*g + m*g*np.sin(np.arctan(0.03)))/(Kp_t+c)*3.6:.3f})")
print(f"3 % hill, PI (Ki = {Ki_t:.2f}): error {err(PI, 55, 60):.4f} km/h")
assert abs(err(P, 55, 60) / ((0.5*rho*CdA*v_ref**2 + Crr*m*g + m*g*np.sin(np.arctan(0.03)))/(Kp_t+c)*3.6) - 1) < 0.02
assert err(P, 55, 60) > 0.5 and abs(err(PI, 55, 60)) < 0.01         # integral action removes the steady error

ZN = simulate(Kp, Kp / Ti, Kp * Td)
print(f"ZN PID on the 3 % hill: peak speed dip {(v_ref - ZN[(ZN[:,0]>20)&(ZN[:,0]<40),1].min())*3.6:.3f} km/h, error at 55-60 s {err(ZN, 55, 60):.4f} km/h")

wind = simulate(Kp_t, Ki_t, 0, steep=True, antiwindup=False)
aw = simulate(Kp_t, Ki_t, 0, steep=True, antiwindup=True)
for name, o in (("no anti-windup", wind), ("clamping anti-windup", aw)):
    after = o[o[:, 0] > 60]
    print(f"8 % hill, {name:20s}: slowest {o[:,1].min()*3.6:.2f} km/h, overshoot after the crest {(after[:,1].max()-v_ref)*3.6:.2f} km/h")
assert (wind[wind[:, 0] > 60, 1].max() - v_ref) > 3 * (aw[aw[:, 0] > 60, 1].max() - v_ref)
```

:::exercise Steady error with P control
A heater needs 400 W to hold 60 °C. A P controller has $K_p = 200$ W/K, and the heat loss rises by 8 W per kelvin of temperature. Estimate the steady error, and the $K_p$ needed for an error below 0.5 K.
---solution---
1. $e_\infty = F_\text{need}/(K_p + c) = 400/(200 + 8) = 1.92$ K, so the heater settles near 58.1 °C.
2. For $e < 0.5$ K: $K_p + 8 > 800$, so $K_p > 792$ W/K. That much gain usually makes a loop with sensor lag oscillate. Adding integral action is the better fix.
:::
