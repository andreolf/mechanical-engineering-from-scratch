A microcontroller board, an Arduino, an ESP32 or a Raspberry Pi Pico, turns a sensor voltage into numbers and sends them to a laptop over USB serial. For a few euros it is a data logger good enough for most lab work, if you know what its analogue-to-digital converter (ADC) can and cannot resolve.

## Resolution and the quantisation step

An $N$-bit ADC with reference voltage $V_\text{ref}$ maps $0 \dots V_\text{ref}$ onto the integer codes $0 \dots 2^N - 1$. One code is a step of

$$
q = \frac{V_\text{ref}}{2^N} .
$$

An Arduino Uno (10 bits, 5 V) has $q = 4.883$ mV. An ESP32 or a Pico (12 bits, 3.3 V) has 0.806 mV, though their real accuracy is worse than the bit count suggests.

## Quantisation noise

Rounding to the nearest code makes an error $e$ between $-q/2$ and $+q/2$. For a busy signal that crosses many codes, $e$ is uniformly distributed, and its standard deviation is

$$
\sigma_e = \sqrt{\frac1q\int_{-q/2}^{q/2} e^2\,de} = \frac{q}{\sqrt{12}} .
$$

For a full-scale sine of amplitude $2^{N-1} q$, the signal power is $(2^{N-1}q)^2/2$, which gives the classic

$$
\text{SNR} = 10\log_{10}\frac{(2^{N-1}q)^2/2}{q^2/12} = 6.02\,N + 1.76 \text{ dB} .
$$

## Averaging and dither

Averaging $M$ readings reduces random noise by $\sqrt M$. But if the analogue signal is quieter than one step, every reading returns the **same** code and averaging changes nothing. Some noise of about $q$ rms, called **dither**, spreads the readings over neighbouring codes, and then the average does resolve finer than $q$. Oversampling with dither is how cheap ADCs buy extra bits.

## A logger you can trust

Serial lines get corrupted: a loose USB cable, a reset mid-line. Each line should carry a **checksum** so the laptop can reject bad lines instead of logging garbage. The firmware below sends `t_ms,ax,ay,az*CS`, where `CS` is the XOR of all bytes before the `*`, in hex (the NMEA convention used by GPS receivers).

```python
# MicroPython on a Raspberry Pi Pico: ADXL335 on ADC0..2, 100 samples per second
from machine import ADC
import time
ch = [ADC(26), ADC(27), ADC(28)]
t0 = time.ticks_ms()
while True:
    a = [c.read_u16() >> 6 for c in ch]          # 16-bit reading scaled to 10 bits
    body = "%d,%d,%d,%d" % (time.ticks_diff(time.ticks_ms(), t0), *a)
    cs = 0
    for b in body.encode(): cs ^= b
    print("%s*%02X" % (body, cs))
    time.sleep_ms(10)
```

:::example Quantisation noise and an accelerometer at rest
1. **Quantisation noise.** For 200 000 random voltages, the rms rounding error is 1.4116 mV at 10 bits and 5 V, against the theory value $q/\sqrt{12} = 1.4095$ mV. At 12 bits and 3.3 V it is 0.2329 mV against 0.2326 mV.
2. **SNR.** A full-scale sine through the 10-bit ADC gives 61.99 dB, against $6.02 \times 10 + 1.76 = 61.96$ dB.
3. **Accelerometer.** An ADXL335 on 3.3 V gives 0.33 V/g with 1.65 V at 0 g. On an Uno one code is $4.883/0.33 = 14.80$ mg.
4. **Quiet sensor** (0.2 mV rms noise): every reading is the same code. Averaging 64 readings leaves a 1.18 mg bias, the distance from 1.65 V to the nearest code, and no spread.
5. **Noisy sensor** (4 mV rms, about $q$): the readings spread over 7 codes, and averages of 64 have a bias of only 0.15 mg with a spread of 1.48 mg. The noise made the average better.
6. **Logger.** The code parses 200 lines from a simulated board, rejects the one corrupted line (its checksum fails), and saves 199 rows to `accel_log.csv`. The mean of the z channel is 1.007 g, which is gravity to within one step.

**Honest note:** no board was connected to the machine that built this course, so the lesson numbers come from the simulated stream. Run `python daq.py --port /dev/ttyACM0` (Windows: `COM3`) with `pyserial` installed to log your own board. The same parser and checks apply.
:::

```python file=daq.py
"""Data acquisition: an ADC model (resolution, quantisation noise q/sqrt(12), SNR = 6.02 N + 1.76 dB)
and a serial logger that parses accelerometer lines with a checksum. Without a board attached it
replays a simulated byte stream; pass --port /dev/ttyACM0 to read a real one (needs pyserial). numpy only."""
import sys, numpy as np

def adc(v, bits, vref):
    """Ideal ADC: round to the nearest code, clip to 0 .. 2^N - 1. Returns codes."""
    return np.clip(np.round(v / vref * 2**bits), 0, 2**bits - 1).astype(int)

rng = np.random.default_rng(5)
# 1) quantisation noise of a busy signal: the error is uniform on [-q/2, q/2]
for bits, vref in ((10, 5.0), (12, 3.3), (16, 3.3)):
    q = vref / 2**bits
    v = rng.uniform(0.1, vref - 0.1, 200_000)
    e = adc(v, bits, vref) * q - v
    print(f"{bits:2d}-bit, Vref {vref} V: q = {q*1e3:.4f} mV, rms error {e.std()*1e3:.4f} mV, theory q/sqrt(12) = {q/np.sqrt(12)*1e3:.4f} mV")
    assert abs(e.std() / (q / np.sqrt(12)) - 1) < 0.01

# 2) SNR of a full-scale sine: 6.02 N + 1.76 dB
bits, vref, n = 10, 5.0, 2**14
t = np.arange(n)
s = vref / 2 + (2**(bits - 1) - 1) * vref / 2**bits * np.sin(2 * np.pi * 1001 / n * t)   # 1001 cycles: not a divisor, so codes do not repeat
err = adc(s, bits, vref) * vref / 2**bits - s
snr = 10 * np.log10(np.mean((s - vref / 2) ** 2) / np.mean(err**2))
print(f"10-bit full-scale sine: SNR {snr:.2f} dB, theory {6.02*bits+1.76:.2f} dB")
assert abs(snr - (6.02 * bits + 1.76)) < 0.3

# 3) an accelerometer at rest on an Arduino Uno: ADXL335 at 3.3 V, 0.33 V/g, 1.65 V at 0 g; 10-bit ADC, Vref 5 V
sens, v0, q = 0.33, 1.65, 5.0 / 1024
print(f"one ADC step = {q*1e3:.3f} mV = {q/sens*1e3:.2f} mg")
quiet = v0 + 0.0002 * rng.standard_normal(4000)          # sensor noise 0.2 mV rms, much less than q
noisy = v0 + 0.004 * rng.standard_normal(4000)           # 4 mV rms (a noisy supply), about q
for name, x in (("quiet", quiet), ("noisy", noisy)):
    c = adc(x, 10, 5.0)
    means = c[: 4000 // 64 * 64].reshape(-1, 64).mean(1) * q
    print(f"{name}: {len(np.unique(c))} distinct codes, averaging 64 readings gives {(means.mean()-v0)/sens*1e3:+.3f} mg bias, spread {means.std()/sens*1e3:.3f} mg")
c = adc(quiet, 10, 5.0); assert len(np.unique(c)) == 1          # stuck on one code: averaging cannot help
m = adc(noisy, 10, 5.0)[:3968].reshape(-1, 64).mean(1) * q
assert abs(m.mean() - v0) < 0.2 * q                              # dither: noise lets averaging resolve below one step

# 4) the logger: lines "t_ms,ax,ay,az*CS" where CS is the XOR of the bytes before '*', in hex
def checksum(body): 
    c = 0
    for ch in body.encode(): c ^= ch
    return f"{c:02X}"
def parse(line):
    line = line.strip()
    if '*' not in line: return None
    body, cs = line.rsplit('*', 1)
    if checksum(body) != cs.upper(): return None
    f = body.split(',')
    return (int(f[0]), *map(int, f[1:])) if len(f) == 4 else None

def simulated_stream(n=200):
    for k in range(n):
        tm = 10 * k
        ax, ay = adc(np.array([v0 + 0.33 * 0.2 * np.sin(2 * np.pi * 1.5 * tm / 1000), v0]), 10, 5.0)
        az = adc(np.array([v0 + 0.33]), 10, 5.0)[0]
        body = f"{tm},{ax},{ay},{az}"
        line = f"{body}*{checksum(body)}\n"
        if k == 57: line = line.replace(',', ';', 1)          # a corrupted line, as a loose wire produces
        yield line

if '--port' in sys.argv:                                      # real hardware: python daq.py --port /dev/ttyACM0
    import serial                                             # pip install pyserial
    port = serial.Serial(sys.argv[sys.argv.index('--port') + 1], 115200, timeout=2)
    lines = (port.readline().decode(errors='replace') for _ in range(2000))
else:
    lines = simulated_stream()
rows, bad = [], 0
for ln in lines:
    r = parse(ln)
    if r is None: bad += 1
    else: rows.append(r)
data = np.array(rows, float)
np.savetxt("accel_log.csv", data, delimiter=",", header="t_ms,ax,ay,az", fmt="%g")
g = (data[:, 1:] * q - v0) / sens
print(f"logged {len(rows)} lines, rejected {bad}; mean az = {g[:, 2].mean():.3f} g, ax amplitude {(g[:,0].max()-g[:,0].min())/2:.3f} g")
if '--port' not in sys.argv:
    assert bad == 1 and len(rows) == 199 and abs(g[:, 2].mean() - 1) < q / sens
```

:::exercise Is 10 bits enough?
You want to measure a bridge output of 0 to 20 mV with 0.1 % of full-scale resolution. The Uno's ADC has 5 V range and 10 bits. What gain do you need in front of it, and is 10 bits enough?
---solution---
1. 0.1 % of full scale needs at least 1000 steps across the range. 10 bits gives 1024, which is just enough if the signal fills the whole range.
2. Gain to map 20 mV to 5 V: $5/0.020 = 250$.
3. Then one step is $4.883\text{ mV}/250 = 19.5$ µV at the bridge, 0.098 % of 20 mV. In practice use a 24-bit bridge ADC such as the HX711 and skip the amplifier.
:::
