Your computer doesn't store real numbers. It stores a finite set of binary fractions, and every operation rounds to the nearest one. Most of the time that's invisible. Sometimes it wipes out every correct digit of an answer. This lesson shows when, why, and how to rewrite a formula so it doesn't happen.

## How a double is stored

An IEEE 754 double has a sign bit, an 11-bit exponent and a 52-bit fraction:

$$
x = (-1)^s \times 1.f_1 f_2 \dots f_{52} \times 2^{e - 1023} .
$$

The gap between 1 and the next representable number is **machine epsilon**,

$$
\varepsilon = 2^{-52} \approx 2.22\times10^{-16} .
$$

Every basic operation is exact, then rounded: $\mathrm{fl}(a \circ b) = (a \circ b)(1 + \delta)$ with $|\delta| \le \varepsilon/2$. So each operation costs at most about 16 significant decimal digits of relative accuracy, which sounds like plenty.

## Absolute and relative error

If $\hat{x}$ approximates $x$, the absolute error is $|\hat{x} - x|$ and the relative error is $|\hat{x} - x| / |x|$. Relative error is the one that counts significant digits: $3.14$ for $\pi$ has relative error $5.1\times10^{-4}$, about three and a half correct digits.

## Catastrophic cancellation

Subtracting two nearly equal numbers is exact, but it exposes the rounding errors they already carried. If $a$ and $b$ each have relative error $\varepsilon$ and agree in their first $k$ digits, then $a - b$ has only about $16 - k$ correct digits left.

Take $f(x) = (1 - \cos x)/x^2$, which tends to $1/2$ as $x \to 0$. For $x = 10^{-8}$, $\cos x = 1 - 5\times10^{-17}$, which rounds to exactly $1$. The numerator becomes $0$ and the result is $0$ instead of $0.5$: a 100% error from a formula that is algebraically perfect.

The fix is to remove the subtraction with an identity before computing:

$$
1 - \cos x = 2\sin^2\frac{x}{2} \quad\Longrightarrow\quad f(x) = \frac{2\sin^2(x/2)}{x^2} .
$$

No nearly equal numbers are subtracted, so the result is accurate to machine precision for every $x$.

:::widget cancel
Absolute error of both formulas against the series $\tfrac12 - \tfrac{x^2}{24}$. As $x$ shrinks the naive error grows like $\varepsilon/x^2$ until it hits 100%; the stable form stays at the bottom.
:::

:::example The quadratic formula that loses a root
Solve $x^2 - 10^8 x + 1 = 0$. The roots are close to $10^8$ and $10^{-8}$.

1. Textbook formula for the small root: $x_2 = \dfrac{b - \sqrt{b^2 - 4}}{2}$ with $b = 10^8$. Here $\sqrt{b^2 - 4}$ agrees with $b$ to 16 digits, so the subtraction cancels them all. In double precision it returns $7.45\times10^{-9}$, a 25% error.
2. Better: compute the large root without cancellation, $x_1 = \dfrac{b + \sqrt{b^2 - 4}}{2}$, then use $x_1 x_2 = c/a = 1$ (Vieta).
3. $x_2 = 1/x_1 = \dfrac{2}{b + \sqrt{b^2 - 4}} = 1.000\times10^{-8}$, correct to every digit.

The physics behind numbers like these is real: a stiff spring next to a soft one, or a tiny damping term next to a large stiffness, produces exactly this kind of quadratic.
:::

```python file=floating.py
"""Machine epsilon, cancellation and two stable rewrites."""
import math


def machine_epsilon():
    eps = 1.0
    while 1.0 + eps / 2 > 1.0:
        eps /= 2
    return eps


def f_naive(x):
    return (1 - math.cos(x)) / x**2


def f_stable(x):
    s = math.sin(x / 2)
    return 2 * s * s / x**2


def quad_roots_naive(a, b, c):
    d = math.sqrt(b * b - 4 * a * c)
    return (-b + d) / (2 * a), (-b - d) / (2 * a)


def quad_roots_stable(a, b, c):
    d = math.sqrt(b * b - 4 * a * c)
    q = -0.5 * (b + math.copysign(d, b))   # no cancellation in q
    return q / a, c / q


if __name__ == "__main__":
    eps = machine_epsilon()
    assert eps == 2.0**-52
    assert abs(f_stable(1e-8) - 0.5) < 1e-10          # the lesson's test
    assert f_naive(1e-8) == 0.0                         # all digits gone
    for x in (1e-1, 1e-3, 1e-5, 1e-7):
        print(f"x={x:.0e}  naive={f_naive(x):.16f}  stable={f_stable(x):.16f}")

    big, small = quad_roots_stable(1.0, -1e8, 1.0)
    _, small_naive = sorted(quad_roots_naive(1.0, -1e8, 1.0))[::-1]
    assert abs(small - 1e-8) / 1e-8 < 1e-15
    assert abs(small_naive - 1e-8) / 1e-8 > 0.2        # 25% wrong
    print(f"small root: naive {small_naive:.6e}, stable {small:.6e}")
```

## Rules of thumb

1. Look for subtractions of nearly equal quantities and rewrite them with identities, conjugates or series.
2. Never test floats with `==`; compare with a tolerance like `abs(a - b) <= rtol * abs(b)`.
3. Sum many small numbers with care (lesson 01.14 builds compensated summation).
4. Expect about 15 to 16 significant digits at best, and fewer after every cancellation.

:::exercise A stable square-root difference
For large $x$, $g(x) = \sqrt{x + 1} - \sqrt{x}$ suffers cancellation. Rewrite it so it's accurate, and evaluate it at $x = 10^{12}$.
---solution---
1. Multiply and divide by the conjugate: $\sqrt{x+1} - \sqrt{x} = \dfrac{(x + 1) - x}{\sqrt{x+1} + \sqrt{x}} = \dfrac{1}{\sqrt{x+1} + \sqrt{x}}$.
2. The new form adds positive numbers only, so no digits cancel.
3. At $x = 10^{12}$: $\dfrac{1}{10^6 + 10^6} = 5.0\times10^{-7}$ (more precisely $4.99999999999875\times10^{-7}$).
4. The naive form keeps only about 5 correct digits here (relative error $7.6\times10^{-6}$), because the two square roots agree to 12 digits.
:::
