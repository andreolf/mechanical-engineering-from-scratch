This course asks you to build every tool yourself, so the first thing you build is the bench you'll work at: a Python environment, a folder for lessons, and a test that tells you when something works. By the end of this lesson you have a repository that runs `pytest` and prints a green line.

## The loop every lesson follows

Each lesson runs the same four steps. You derive the model by hand, write the code from nothing, prove it with a test, and keep the result in your repository. The test is the part that turns a script into engineering: it states what "correct" means before you look at the output.

## What a passing artifact looks like

An artifact passes when three things hold:

- It runs from a fresh clone with one command
- Its test compares the result against something you trust independently: a hand calculation, an analytic limit, or a conservation law
- The tolerance in the test is justified, not tuned until it passes

The third point is the one people skip. If your test says `abs(x - 3.0) < 0.5` because 0.5 made it pass, the test proves nothing. Later lessons show you how to pick tolerances from the size of truncation and round-off error.

## Setting up the environment

You need Python 3.10 or newer. A virtual environment keeps this course's packages separate from everything else on your machine, so an upgrade elsewhere can't break a lesson you finished months ago.

```bash
python3 -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install numpy scipy matplotlib sympy pytest
mkdir -p lessons tests
```

The repository layout stays the same for the whole course: lesson code in `lessons/`, tests in `tests/`, one file per lesson.

:::example Checking your toolchain with a real test
The smoke test below checks two things you'll rely on constantly: that NumPy is installed, and that floating-point arithmetic behaves the way IEEE 754 says it should. The sum $0.1 + 0.2$ is not exactly $0.3$ in binary floating point; the difference is $5.55 \times 10^{-17}$, one unit in the last place of a number near 0.3. A test that compares with `==` would fail here, which is why every numeric test in this course uses a tolerance.

With $\varepsilon = 2^{-52} \approx 2.22 \times 10^{-16}$ (machine epsilon for doubles), the error is $\varepsilon/4$, so a tolerance of $10^{-12}$ is safe by four orders of magnitude.
:::

```python file=smoke_test.py
import sys
import numpy as np


def toolchain_report():
    """Return the facts the rest of the course depends on."""
    eps = np.finfo(float).eps
    return {
        "python": sys.version_info[:2],
        "numpy": np.__version__,
        "eps": eps,
        "sum_error": abs((0.1 + 0.2) - 0.3),
    }


def test_toolchain():
    r = toolchain_report()
    assert r["python"] >= (3, 10)
    assert r["eps"] == 2.0 ** -52
    # 0.1 + 0.2 misses 0.3 by a quarter of machine epsilon
    assert r["sum_error"] == r["eps"] / 4
    assert abs((0.1 + 0.2) - 0.3) < 1e-12


if __name__ == "__main__":
    test_toolchain()
    print("toolchain OK:", toolchain_report())
```

Run it with `python smoke_test.py`, then with `pytest -q`. Both should pass. Commit the file: it's your first artifact.

:::exercise Write a test that fails for the right reason
Write a function `mean(xs)` and a test for it. Then deliberately break the function (for example, divide by `len(xs) + 1`) and confirm the test fails. What tolerance did you use for the comparison, and why?
---solution---
1. A correct implementation is `def mean(xs): return sum(xs) / len(xs)`.
2. Test it against a case you can compute by hand: `mean([1, 2, 3, 4])` is exactly 2.5. The inputs are small integers, so the sum is exact in floating point and you can use a tight tolerance such as `1e-12`.
3. The broken version returns $10/5 = 2.0$, an error of 0.5, far outside $10^{-12}$, so the test fails.
4. The tolerance is justified because the only error source is the final division, which is accurate to within half a unit in the last place (about $2.8 \times 10^{-16}$ for 2.5).
:::

:::exercise Make the repository reproducible
Add a `requirements.txt` that pins the package versions you installed, then recreate the environment in a new folder and run the smoke test there.
---solution---
1. Run `pip freeze > requirements.txt` inside the activated environment.
2. In a new folder: `python3 -m venv .venv`, activate it, then `pip install -r requirements.txt`.
3. Copy `smoke_test.py` across and run `pytest -q`. A pass shows the environment is reproducible from the file alone.
:::
