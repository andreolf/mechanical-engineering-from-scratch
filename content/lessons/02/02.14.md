In a finite-element model each node only talks to its neighbours, so each row of the stiffness matrix has a handful of nonzeros, however many nodes there are. Storing and solving such matrices as if they were dense would be absurd. Sparse storage and solvers that respect the zeros turn impossible problems into routine ones.

## How sparse is sparse?

A 1D bar split into $n$ elements has a tridiagonal stiffness matrix: three nonzeros per row. For $n = 10^6$:

- Dense: $n^2 = 10^{12}$ entries $\times$ 8 bytes = 8 TB, and $\tfrac23 n^3 \approx 7\times10^{17}$ operations to solve.
- Tridiagonal: $3n$ entries = 24 MB, and about $8n$ operations to solve.

A 2D grid with the 5-point stencil has five nonzeros per row; a 3D hexahedral FEM mesh has around 81. Still tiny compared with $n$.

## Compressed sparse row (CSR)

Store only the nonzeros, row by row, in three arrays:

- `data`: the values,
- `indices`: the column of each value,
- `indptr`: where each row starts in `data` (length $n + 1$).

The product $A\mathbf x$ then loops over the stored entries only: cost proportional to the number of nonzeros, not $n^2$.

## Direct solvers and fill-in

Elimination on a sparse matrix can create new nonzeros ("fill-in"). For a tridiagonal matrix there's none, and elimination becomes the **Thomas algorithm**, $O(n)$. For a banded matrix with half-bandwidth $b$, LU costs $O(nb^2)$. For general meshes, sparse direct solvers reorder the unknowns first (nested dissection, minimum degree) to keep fill-in small. For the largest 3D problems even that is too much, and iterative solvers (lesson 02.15) take over.

:::example A long bar, by the numbers
A steel bar is modelled with $n = 2000$ unknowns, a tridiagonal stiffness matrix.

1. Dense storage: $2000^2\times8 = 32$ MB. Tridiagonal storage: $3\times2000\times8 = 48$ kB, about 670 times less.
2. Dense LU: $\tfrac23\cdot2000^3 = 5.3\times10^9$ operations. Thomas: about $8\times2000 = 1.6\times10^4$.
3. In CSR, the 4 × 4 version in the figure stores 10 values and 10 column indices, plus 5 row pointers.
4. Measured in the code below (pure Python Thomas versus NumPy's optimised dense solver): Thomas wins even though it's interpreted Python, and the gap widens as $n$ grows because it scales linearly.
:::

```python file=sparse.py
"""CSR storage and matrix-vector product, and the Thomas algorithm for tridiagonal systems."""
import time
import numpy as np


class CSR:
    def __init__(self, dense, tol=0.0):
        self.n = len(dense); self.data, self.indices, self.indptr = [], [], [0]
        for row in dense:
            for j, v in enumerate(row):
                if abs(v) > tol:
                    self.data.append(float(v)); self.indices.append(j)
            self.indptr.append(len(self.data))

    @classmethod
    def tridiag(cls, lower, diag, upper):
        m = cls([]); n = len(diag); m.n = n
        for i in range(n):
            if i > 0: m.data.append(lower[i - 1]); m.indices.append(i - 1)
            m.data.append(diag[i]); m.indices.append(i)
            if i < n - 1: m.data.append(upper[i]); m.indices.append(i + 1)
            m.indptr.append(len(m.data))
        return m

    def matvec(self, x):
        return [sum(self.data[k] * x[self.indices[k]] for k in range(self.indptr[i], self.indptr[i + 1])) for i in range(self.n)]


def thomas(a, b, c, d):
    """Solve a tridiagonal system: a = sub-diagonal (n-1), b = diagonal (n), c = super-diagonal (n-1)."""
    n = len(b); cp = [0.0] * (n - 1); dp = [0.0] * n
    cp[0] = c[0] / b[0] if n > 1 else 0.0; dp[0] = d[0] / b[0]
    for i in range(1, n):
        m = b[i] - a[i - 1] * cp[i - 1]
        if i < n - 1: cp[i] = c[i] / m
        dp[i] = (d[i] - a[i - 1] * dp[i - 1]) / m
    x = [0.0] * n; x[-1] = dp[-1]
    for i in range(n - 2, -1, -1):
        x[i] = dp[i] - cp[i] * x[i + 1]
    return x


if __name__ == "__main__":
    A4 = [[2, -1, 0, 0], [-1, 2, -1, 0], [0, -1, 2, -1], [0, 0, -1, 1]]
    m = CSR(A4)
    assert m.data == [2, -1, -1, 2, -1, -1, 2, -1, -1, 1] and m.indptr == [0, 2, 5, 8, 10]
    assert m.matvec([1, 2, 3, 4]) == list(np.array(A4) @ [1, 2, 3, 4])
    for n in (500, 2000):
        a = [-1.0] * (n - 1); c = [-1.0] * (n - 1); b = [2.0] * n; b[-1] = 1.0
        d = [0.0] * n; d[-1] = 1.0                        # pull on the free end of a spring chain
        t = time.perf_counter(); x = thomas(a, b, c, d); tt = time.perf_counter() - t
        K = np.diag(b) + np.diag(a, -1) + np.diag(c, 1)
        t = time.perf_counter(); xd = np.linalg.solve(K, d); td = time.perf_counter() - t
        assert np.allclose(x, np.arange(1, n + 1)) and np.allclose(x, xd)
        assert np.allclose(CSR.tridiag(a, b, c).matvec(x), d)
        print(f"n = {n}: Thomas (Python) {tt*1e3:6.2f} ms, dense LU (NumPy) {td*1e3:6.2f} ms, dense storage {n*n*8/1e6:5.1f} MB vs {3*n*8/1e3:5.1f} kB")
```

:::exercise Count the nonzeros
A square plate is meshed with a $300\times300$ grid of unknowns using the 5-point stencil. How many unknowns, how many nonzeros (ignore the boundary effect), and how much memory do CSR and dense storage need with 8-byte values and 4-byte indices?
---solution---
1. Unknowns: $n = 90\,000$.
2. Nonzeros: about $5n = 450\,000$.
3. CSR: values $450\,000\times8 = 3.6$ MB, column indices $450\,000\times4 = 1.8$ MB, row pointers $90\,001\times4 \approx 0.36$ MB, so about 5.8 MB.
4. Dense: $n^2\times8 = 8.1\times10^9\times8 \approx 65$ GB. More than most laptops have.
:::
