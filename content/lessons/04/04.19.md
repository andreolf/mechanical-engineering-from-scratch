Lighter brackets, stiffer frames, cheaper pipe networks, controllers that settle faster: design is optimisation. Phase 02 solved least squares, the one optimisation problem with a closed-form answer. Most design problems need iterative methods that walk downhill on an objective function. This lesson builds the two you'll meet most: gradient descent, which is simple but slow on badly scaled problems, and BFGS, the quasi-Newton workhorse behind `scipy.optimize.minimize`.

## Gradient descent and line search

Step against the gradient, $\mathbf x_{k+1} = \mathbf x_k - \alpha_k\nabla f(\mathbf x_k)$. A fixed step is either too timid or unstable. A **backtracking line search** starts from $\alpha = 1$ and halves it until the **Armijo condition** holds:

$$
f(\mathbf x + \alpha\mathbf p) \le f(\mathbf x) + c_1\alpha\,\nabla f^{\mathsf T}\mathbf p, \qquad c_1 = 10^{-4}.
$$

This guarantees a real decrease. But in a long, narrow valley the gradient points mostly across the valley, not along it, so the iterates zig-zag. The number of iterations grows with the condition number of the Hessian (lesson 03.03).

## Newton and quasi-Newton

Newton's method for optimisation uses the Hessian: solve $H\mathbf p = -\nabla f$. It rescales the problem so every valley looks round, and converges quadratically near the minimum. But Hessians are expensive or unavailable. **BFGS** builds an approximation of $H^{-1}$ from the gradients it has already seen. With $\mathbf s = \mathbf x_{k+1} - \mathbf x_k$, $\mathbf y = \nabla f_{k+1} - \nabla f_k$ and $\rho = 1/(\mathbf y^{\mathsf T}\mathbf s)$:

$$
H^{-1}_{k+1} = \left(I - \rho\,\mathbf s\mathbf y^{\mathsf T}\right)H^{-1}_k\left(I - \rho\,\mathbf y\mathbf s^{\mathsf T}\right) + \rho\,\mathbf s\mathbf s^{\mathsf T}.
$$

The update satisfies the **secant condition** $H^{-1}_{k+1}\mathbf y = \mathbf s$ (the multidimensional version of the secant method from 04.02) and stays positive definite as long as $\mathbf y^{\mathsf T}\mathbf s > 0$. Convergence is superlinear, and each iteration needs only one gradient.

## The Rosenbrock valley

$f(x_1, x_2) = (1 - x_1)^2 + 100(x_2 - x_1^2)^2$ has its minimum at $(1, 1)$, at the end of a curved, banana-shaped valley. It's the standard torture test for optimisers.

:::widget rosen
Paths from the classic start $(-1.2, 1)$ on the Rosenbrock valley (brighter is higher). BFGS turns along the curved floor and reaches $(1, 1)$ in a few dozen steps; steepest descent crawls in tiny zig-zags.
:::

:::example Rosenbrock from $(-1.2, 1)$
Both methods use the same Armijo backtracking and stop when $\|\nabla f\| < 10^{-10}$.

1. BFGS: reaches $(1.00000000, 1.00000000)$ in 36 iterations. SciPy's BFGS (with a stronger Wolfe line search) needs 32.
2. Gradient descent: 25 115 iterations to the same tolerance, about 700 times more.
3. Why: at the minimum the Hessian is $\begin{pmatrix}802 & -400\\-400 & 200\end{pmatrix}$, with condition number about 2500. Steepest descent pays for that ratio; BFGS learns it.
:::

```python file=bfgs.py
"""Gradient descent versus BFGS with an Armijo backtracking line search on the Rosenbrock valley."""
import numpy as np


def rosen(x):
    return (1 - x[0]) ** 2 + 100 * (x[1] - x[0] ** 2) ** 2


def rosen_grad(x):
    return np.array([-2 * (1 - x[0]) - 400 * x[0] * (x[1] - x[0] ** 2), 200 * (x[1] - x[0] ** 2)])


def armijo(f, x, fx, g, p, c1=1e-4, shrink=0.5):
    """Backtrack from a full step until the decrease is at least c1 * alpha * g.p."""
    a, slope = 1.0, g @ p
    while f(x + a * p) > fx + c1 * a * slope:
        a *= shrink
    return a


def bfgs(f, grad, x, tol=1e-10, maxit=500):
    n = len(x); Hinv = np.eye(n); g = grad(x); path = [x.copy()]; evals = 0
    for k in range(maxit):
        if np.linalg.norm(g) < tol:
            break
        p = -Hinv @ g
        a = armijo(f, x, f(x), g, p)
        s = a * p; x_new = x + s; g_new = grad(x_new); y = g_new - g
        if y @ s > 1e-12:                               # curvature condition keeps Hinv positive definite
            rho = 1 / (y @ s); I = np.eye(n)
            Hinv = (I - rho * np.outer(s, y)) @ Hinv @ (I - rho * np.outer(y, s)) + rho * np.outer(s, s)
        x, g = x_new, g_new; path.append(x.copy())
    return x, k, np.array(path)


def gradient_descent(f, grad, x, tol=1e-10, maxit=100_000):
    g = grad(x)
    for k in range(maxit):
        if np.linalg.norm(g) < tol:
            break
        p = -g
        x = x + armijo(f, x, f(x), g, p) * p; g = grad(x)
    return x, k


if __name__ == "__main__":
    x0 = np.array([-1.2, 1.0])                          # the classic start
    xb, kb, path = bfgs(rosen, rosen_grad, x0.copy())
    xg, kg = gradient_descent(rosen, rosen_grad, x0.copy())
    print(f"BFGS: ({xb[0]:.8f}, {xb[1]:.8f}) after {kb} iterations")
    print(f"gradient descent: ({xg[0]:.6f}, {xg[1]:.6f}) after {kg} iterations")
    assert np.linalg.norm(xb - 1) < 1e-6 and kb < 100
    assert kg > 20 * kb
    from scipy.optimize import minimize
    r = minimize(rosen, x0, jac=rosen_grad, method="BFGS")
    print(f"scipy BFGS: {r.nit} iterations, x = {r.x.round(6)}")
```

:::exercise One Armijo backtrack
At $\mathbf x = (-1.2, 1)$, $f = 24.2$ and $\nabla f = (-215.6, -88)$. Taking $\mathbf p = -\nabla f$, does the full step $\alpha = 1$ satisfy Armijo? Roughly what step will be accepted?
---solution---
1. $\nabla f^{\mathsf T}\mathbf p = -(215.6^2 + 88^2) = -54\,227$. The full step lands at $(214.4, 89)$, where $f$ is about $2\times10^{11}$. Armijo fails badly.
2. Halving repeatedly, Armijo first holds after 10 halvings: $\alpha = 2^{-10} \approx 0.001$, a move of $(0.21, 0.09)$. The step had to shrink to the width of the valley.
3. This is why scaling matters: one badly scaled direction forces tiny steps in all of them. BFGS's $H^{-1}$ fixes the scaling after a few iterations.
:::
