A simulation produces beautiful colour plots whether it is right or not. Before anyone builds a part on the strength of your results, two questions must have documented answers. **Verification**: are we solving the equations right? (Is the code a correct implementation of the model?) **Validation**: are we solving the right equations? (Does the model match reality?) This lesson gives you the sharpest verification tool there is, the method of manufactured solutions, and closes Phase 04 by turning everything you have built into something you can trust.

## Code verification by observed order

Every discretisation in this phase has a theoretical order $p$. If the code is correct, refining the grid must make the error fall like $h^p$. The test needs an exact solution to measure the error against, and real problems rarely have one.

## The method of manufactured solutions

Turn the problem around: **choose** the solution first, then compute what source term and boundary data produce it.

1. Pick a smooth $u_m(x, y)$ that exercises every term: not a polynomial the scheme reproduces exactly, not a single eigenmode, with nonzero boundary values. For example $u_m = \sin(\pi x)e^y + xy^2$.
2. Derive the source by applying the operator by hand (or with computer algebra): $f = -\nabla^2u_m = (\pi^2 - 1)\sin(\pi x)e^y - 2x$.
3. Run the solver with that $f$ and boundary values $u_m$ on a sequence of grids.
4. Measure the error and the **observed order** $p_{\text{obs}} = \log_2(E_h/E_{h/2})$. Pass if it approaches the theoretical order.

The manufactured solution needn't be physical. It's a test pattern, and a far stricter test than "the plot looks plausible": a bug that adds an $O(h)$ error passes every eyeball check and fails MMS immediately.

## Solution verification and validation

- **Solution verification** estimates the discretisation error of a real run, where no exact solution exists: compute on three grids, check that the observed order is near theory, and extrapolate (Richardson, lesson 04.01). Report the estimated uncertainty, not just the answer.
- **Validation** compares the verified model with experiments, with uncertainties on both sides. A mismatch then points at the physics (material model, boundary conditions, turbulence model), not at the code.

Only verified codes can be meaningfully validated. Calibrating a buggy code to match an experiment just hides the bug until the next design.

:::widget mmsorder
Max error of a 2D Poisson solver against the manufactured solution as the grid is refined. The correct 5-point solver follows the slope-2 guide. Plant an off-by-one in the grid spacing and the errors stay small and plausible, but the slope drops to 1.
:::

:::example Catching a planted bug
The 5-point Poisson solver on the unit square with $u_m = \sin(\pi x)e^y + xy^2$ (maximum value 3.22):

| $n$ | 8 | 16 | 32 | 64 | 128 |
|---|---|---|---|---|---|
| correct: max error | $1.32\times10^{-2}$ | $3.34\times10^{-3}$ | $8.36\times10^{-4}$ | $2.09\times10^{-4}$ | $5.23\times10^{-5}$ |
| bug: max error | $1.65\times10^{-1}$ | $9.41\times10^{-2}$ | $5.02\times10^{-2}$ | $2.59\times10^{-2}$ | $1.32\times10^{-2}$ |

Observed orders: correct 1.98, 2.00, 2.00, 2.00; buggy 0.81, 0.91, 0.95, 0.98. The buggy solver's error at $n = 128$ is only 0.4% of the solution, and its contour plots are indistinguishable by eye. Only the order gives it away.
:::

```python file=mms.py
"""Verification by the method of manufactured solutions: pick u, derive f, check the observed order of a 2D Poisson solver."""
import math
import numpy as np
import scipy.sparse as sp
import scipy.sparse.linalg as spla

# manufactured solution (not a polynomial, not separable into one Fourier mode, nonzero boundary values)
u_m = lambda x, y: np.sin(math.pi * x) * np.exp(y) + x * y**2
# f = -lap u, derived by hand: -(-pi^2 sin(pi x) e^y + sin(pi x) e^y + 2x)
f_m = lambda x, y: (math.pi**2 - 1) * np.sin(math.pi * x) * np.exp(y) - 2 * x


def poisson_solve(n, f, g, bug=False):
    """5-point Laplacian on the unit square with Dirichlet data g. bug=True plants a classic mistake."""
    h = 1.0 / n; m = n - 1
    x = np.linspace(0, 1, n + 1); X, Y = np.meshgrid(x, x, indexing="ij")
    T = sp.diags([-1.0, 2.0, -1.0], [-1, 0, 1], shape=(m, m))
    I = sp.identity(m)
    hA = 1.0 / (n + 1) if bug else h                  # the planted bug: an off-by-one grid spacing in the matrix
    A = (sp.kron(T, I) + sp.kron(I, T)) / hA**2
    b = f(X[1:-1, 1:-1], Y[1:-1, 1:-1]).copy()
    G = g(X, Y)
    b[0, :] += G[0, 1:-1] / hA**2; b[-1, :] += G[-1, 1:-1] / hA**2
    b[:, 0] += G[1:-1, 0] / hA**2; b[:, -1] += G[1:-1, -1] / hA**2
    U = G.copy(); U[1:-1, 1:-1] = spla.spsolve(A.tocsc(), b.ravel()).reshape(m, m)
    return X, Y, U


def observed_orders(bug=False, ns=(8, 16, 32, 64, 128)):
    errs = []
    for n in ns:
        X, Y, U = poisson_solve(n, f_m, u_m, bug)
        errs.append(np.max(np.abs(U - u_m(X, Y))))
    return errs, [math.log2(a / b) for a, b in zip(errs, errs[1:])]


if __name__ == "__main__":
    # check the hand derivation of f with a finite-difference Laplacian of u at a point
    x0, y0, d = 0.3, 0.7, 1e-4
    lap = (u_m(x0 + d, y0) + u_m(x0 - d, y0) + u_m(x0, y0 + d) + u_m(x0, y0 - d) - 4 * u_m(x0, y0)) / d**2
    assert abs(-lap - f_m(x0, y0)) < 1e-4
    errs, p = observed_orders()
    print("correct solver: errors", " ".join(f"{e:.2e}" for e in errs), "| observed orders", " ".join(f"{q:.3f}" for q in p))
    assert abs(p[-1] - 2) < 0.02
    errs_b, p_b = observed_orders(bug=True)
    print("planted bug:    errors", " ".join(f"{e:.2e}" for e in errs_b), "| observed orders", " ".join(f"{q:.3f}" for q in p_b))
    assert errs_b[-1] < 0.02 and abs(p_b[-1] - 1) < 0.1     # small errors that look fine, but first order: MMS exposes it
```

:::exercise Manufacture a source term
For the 1D heat equation $u_t = \alpha u_{xx} + s(x, t)$, manufacture $u_m = e^{-t}\sin(2x) + x^2$. What source $s$ must you add, and what boundary data at $x = 0$ and $x = \pi$?
---solution---
1. $u_t = -e^{-t}\sin2x$ and $u_{xx} = -4e^{-t}\sin2x + 2$.
2. $s = u_t - \alpha u_{xx} = -e^{-t}\sin2x + 4\alpha e^{-t}\sin2x - 2\alpha = (4\alpha - 1)e^{-t}\sin2x - 2\alpha$.
3. Boundary values: $u(0, t) = 0$ and $u(\pi, t) = \pi^2$; initial condition $u(x, 0) = \sin2x + x^2$. Run FTCS and Crank-Nicolson (04.14) with this $s$: the observed orders in time should be 1 and 2.
:::
